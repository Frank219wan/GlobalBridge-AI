五人分工版 ・ 2026 年 11 月 25 日 ・ 开发与测试执行方案


承接《GlobalBridge AI 比赛 MVP 产品需求文档》。两周内交付全部 P0。演示主线为深圳智能家居传感器制造商
开拓德国市场，使用预设 Demo 账号，交付 Web 与复用 Web 的 Windows 程序。本方案中的技术选型、字段和
阈值为开工建议。数据保存方案仍待团队拍板。


1 技术栈与部署拓扑
推荐采用一个 Next.js 全栈应用、一套 PostgreSQL，以及一个 WebView2 Windows 壳。
五人分别负责平台、市场、询盘、报价和双端交付。两个客户端访问同一 HTTPS 应用和业务记录。

浏览器 / Windows WebView2 → HTTPS → Next.js 页面与业务接口 → PostgreSQL、Zhihu 官方 API、海外
搜索 API、模型 API

 层级                推荐方式与开工依据

                   享请求和响应的字段约定，服务端重新校验用户输入。Next.js Route Handlers

                   供应商。模型首测百炼 Qwen3.7-Flash 系列，重点验证所选地域和模型 ID 的结构化输出、德英邮
                   件、成本及延迟。供应商凭证由服务端保管。知乎开放平台 · 百炼结构化输出


建议部署一个 Node.js 应用实例，接同区域的持久数据库，由 HTTPS 入口对外提供访问。正式演示和开发测试使

在拟部署环境跑通真实请求和 Windows 最小试装，在本机成功只算开发验证。

核心状态与异常约定
• 读取与更新。 未登录为 401。缺失或其他工作区的记录返回 404。字段错误为 422，版本或重复键内容冲突为
  409，达到工作区限额为 429。外部服务全部失败时为 503，整体时限耗尽且无可用结果时为 504。单源失败且
  仍有可用结果时返回 200 和 partial，对应信源标明原因。各源正常响应且无命中时显示 empty。模型归纳失败
  时仍显示有效来源，报告标为待重试。

4 数据库结构与领域规则
主要业务表均有 UUID 主键、workspace_id、created_at 和 updated_at，可编辑记录有版本号。租户边界按工作
区建立，关联查询同时限制工作区与记录 ID。PostgreSQL 建议通过组合外键约束跨工作区关联。列表索引为工作
区与更新时间，客户增加官网域唯一约束。

  期模糊时保留原句，避免猜补。数量缺失返回空值，区别于业务值 0。

• 报价规则建议。 单行、USD/EUR、数量为正整数，演示可设上限 1,000,000。单价为大于零且最多两位小数的金
