01 项目定位与决策
面向中国中小制造企业的 AI 外贸业务助手，首版以比赛现场可操作演示为目标。


产品目标与目标用户
让制造商、供应商以及缺少专业外贸团队的业务人员复用同一份产品资料，完成海外市场分析、潜在客户
发现、采购询盘处理、多语言商务回复和报价生成。演示成果应可追溯、可保存，并在两端重新打开。


已确认决策及开发基线

 决策               状态      基线

 使用场景             已确认     比赛 Demo，优先保证真实可运行和完整演示。

 开发范围             已确认     完整实现原方案全部 P0，P1 与 P2 后续安排。

 产品形态             已确认     Web 为主要入口，同时交付 Windows 桌面端。

 桌面端形式            已确认     使用 Web 技术封装 Windows 应用，共用业务界面。

 登录方式             已确认     预设 Demo 账号，进入固定演示工作空间。

 数据来源             已确认方向   优先寻找真实、稳定、低成本的 API，具体服务须实测。

 数据保存             尚未决定    推荐统一云端 PostgreSQL，开发前记录批准结果。

 开发期限             已确认     14 天。



德国市场演示主线
录入深圳演示企业与智能家居传感器的规格和价格 → 选择德国并调用知乎官方能力 → 搜索真实候选企业
并核对来源 → 查看客户详情和匹配理由 → 粘贴采购询盘 → 提取采购需求、缺项与风险 → 生成并编辑英
文或德文回复 → 生成并保存报价 → 在 Web 和 Windows 端重新打开记录。

演示产品示例为 Smart Home Sensor，型号 SHS-001，币种 USD。规格和单价由操作者录入或确认。


  交付结果
  提供可访问的 Web 系统、通过 Windows 实机测试的安装包，以及能够从产品录入连续运行到报价保
  存的演示流程。

02 功能范围与优先级
P0 为 14 天交付范围。P1、P2 供后续版本安排。


P0 必须实现

 模块               功能要求

 演示访问             预设 Demo 账号和固定工作空间。Web 与 Windows 使用同一业务数据。

 企业与产品            录入及编辑企业名称、国家或所在地、简介和主营业务。产品可新建、查看、编辑、
                  删除，含名称、类别、特点、用途、型号、规格、价格、币种和计价单位。

 市场发现             选择产品和目标国家。接入至少一项真实知乎官方能力，检索海外公开信息，展示
                  市场概况、需求与机会、竞争情况和客户推荐。

 客户情报             搜索真实海外候选企业。展示名称、国家、官网、主营业务、匹配理由、公开来源

 询盘处理             粘贴询盘文本，提取产品、数量、规格、目的地、交期、付款条件，并列出缺失项、

 商务邮件             根据产品资料和询盘生成邮件，至少支持两种语言，演示覆盖英文和德文，中文可
                  选配。支持编辑、重新生成、复制和保存草稿。

 报价管理             从产品和询盘生成可编辑报价草稿，校验缺项，按规则计算金额并保存，支持查看
                  历史报价。

 仪表盘与保存           展示业务数量和最近记录，保存企业、产品、市场分析、客户、询盘和报价，支持
                  端到端演示。

03 推荐技术架构
统一 Web 前端和业务后端。Windows 应用复用同一套界面，双端读取同一份业务记录。

技术选型

 层级               推荐方案                          用途与状态

 Web              React + TypeScript + Vite     共享组件、页面、表单和交互逻辑。

 Windows          Tauri 2                       封装共享界面。第 1–2 天验证 Rust、C++ Build

 后端               FastAPI（Python）               统一认证、数据处理与外部服务编排。

 数据库              PostgreSQL / Supabase         PostgreSQL 为推荐存储，Supabase 为托管候选。
                                                核查连接、资源和暂停条件。

 AI 模型            支持结构化输出的大模型 API               提取询盘、解释匹配、生成邮件及辅助整理报价。
                                                供应商待选。

 部署               静态前端 + Python 后端托管            保障线上演示，具体平台待部署测试。


数据存储选择
云端 PostgreSQL 易于双端共享，依赖赛场网络和云服务。本地 SQLite 便于离线，双端同步成本较高。
云端加本地同步会增加开发和测试复杂度。首版建议采用云端统一存储，赛前导出可恢复备份。

04 真实数据源与验证
优先验证真实接口、返回质量和使用成本。官方文档可查，项目凭证及实际可用性待验证。


知乎官方数据开放平台 / 候选能力待实测
优先验证问题推荐或问题发现，用于定位产品和行业话题。测试问题回答或摘要能否提取应用场景、用户
关注点与常见问题。需确认 Access Secret、权限、可用额度、返回字段和内容展示条件。

海外企业搜索 / Brave Search API 待实测
以 Brave Web Search 为优先候选，利用国家和语言参数检索德语网站。按产品和目标国家生成英文及德
文关键词，检索并筛选相关企业官网，提取企业名称、官网和经营范围。匹配理由由 AI 依据来源说明，缺
项标记为“暂无可靠信息”或“待核实”。

存在公开线索，采购状态及合作意愿需要另行核实。

接入验收门槛

 检查项                通过条件

 知乎官方调用             项目凭证能完成至少一次真实调用，结果可用于计划中的展示。

 海外搜索               项目请求能返回相关、可访问的公开企业网页。

 来源可追溯              页面可打开原始链接，记录来源、时间和状态。

05 模块依赖与数据结构

模块依赖

 模块               上游输入                   形成的记录或结果

 基础层              Demo 身份、工作空间、数据库       可复用的企业与产品资料。

 市场发现             产品、目标国家、知乎与海外搜索        市场分析、候选企业及来源。

 客户情报             企业公开资料、当前产品与来源         客户详情、匹配理由、核实状态。

 询盘分析             产品资料、询盘文本及客户（可空）       结构化需求、缺失项、风险和追问建议。

 商务沟通             产品、客户与询盘分析             可编辑及版本化的邮件草稿。

 智能报价             规格、数量、单价、币种与贸易条件       可编辑报价及价格快照。

 业务仪表盘            跨模块业务记录                统计、最近记录和继续操作入口。


核心数据实体

 实体                      必需字段与关联

 DemoUser                ID、账号标识、工作空间。

 MarketResearch          ID、产品 ID、目标国家、分析结果及来源。

07 交互状态与业务规则
用户能看见处理进度和数据来源，能修正缺项，并确认最终业务内容。


AI 与搜索页面状态

 状态               行为

 未开始              展示输入项、操作说明和当前关联对象。

 正在处理             显示加载或处理中状态，避免重复提交。

 成功               显示结果、适用的来源和可继续执行的操作。

 无结果              说明未找到可靠信息，可调整条件后重试。

 信息不完整            标记缺项并允许人工补齐，保留其他已填信息。

 API 失败           对超时、限额和其他调用异常提供明确反馈与重试入口。

 保存失败             保留可编辑内容，显示失败并允许重试。


商务邮件与报价

 规则               要求

 邮件草稿             选择语言，可提供正式、专业或简洁风格。使用已知产品和询盘信息，用户可编
                  辑、重新生成、复制并保存，自行确认后使用。

 报价字段             企业、客户、产品、规格、数量、单价、币种、总价、贸易条件、有效期。贸易
                  条件与有效期由用户确认或填写。

 金额计算             由后端按确定规则计算。价格或数量缺失时提示补齐，依据用户实际输入计入运
                  费及税费。

 价格快照             新报价读取当前产品价格，历史报价保留已保存时的价格和明细。


数据质量与操作反馈
询盘缺项由用户补充，AI 不得补造数量、交期、付款条件、价格、客户联系方式或商务承诺。客户信息和
市场结论显示来源或待核实状态。新增、编辑、删除等操作需要明确的成功或失败反馈，删除前应提示确
认。


  实时搜索异常
  显示当前不可用或无可靠结果。使用预置历史样例时，显著展示来源、时间和演示标记。

三个关键决策点

 时点               判断与行动

 第2天              验证知乎官方调用与海外企业搜索。失败时立即检查替代接口和演示影响，将对应

10 质量与最终验收
以下为比赛交付的内部验收目标。以项目实测记录确认结果。


最终验收清单

 验收项              通过标准

 核心业务流程           完成企业与产品录入、德国市场发现、客户选择、询盘分析、编辑商务回复并
                  保存报价。

 真实数据与来源          成功调用至少一项知乎官方能力并展示结果。找到真实海外企业，能打开来源、
                  查看匹配理由及核实状态。

 询盘分析             准备 10 个样例，人工核对产品、数量、规格、目的地、交期、付款条件及缺项
                  与风险提示。

 AI 可靠性           邮件与分析遵循输入和来源。价格、客户信息及付款或交付承诺均须有依据。

 报价计算             预备计算用例全部通过，覆盖缺项、规则计算和历史单价快照。

 数据保存             刷新或重新登录后找回客户、市场分析、询盘、邮件和报价等已保存记录。

 跨端一致性            Web 与 Windows 使用同一 Demo 工作空间并显示相同业务记录。

 API 异常处理         对超时、限额、空结果和保存失败提供明确反馈。历史样例具有醒目标识。

 Windows 交付       安装、启动、登录及核心流程通过 Windows 实机人工测试。

 演示可靠性            赛前连续完成至少 3 次全链路演示。


非功能要求
安全方面，外部服务密钥仅保存在后端，Web 和桌面安装包均不得包含。Demo 账号也需由服务端鉴权并
限制工作空间访问。日志避免保存完整敏感采购邮件。

性能方面，普通页面读取以 3 秒以内为建议目标。AI 和搜索任务允许更长等待，需提供可见处理状态、超
时与重试。
