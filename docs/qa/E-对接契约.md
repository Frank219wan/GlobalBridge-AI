# E ↔ 队友对接契约

给 A / B / C / D 的最小请求，全部落在**已有文件之外**的 E 目录内，不改动各位的代码结构。
每条都标注了“E 需要什么 / 谁提供 / 什么时候要 / 不提供时 E 怎么降级”。

## 1. 给 A（平台与资料）

| 需求 | 内容 | 何时 | 无此项时的降级 |
| --- | --- | --- | --- |
| 部署地址 | 唯一 HTTPS 根地址，含 `/login` 路径 | D2 | 用 `--url=` 占位地址验证壳行为，业务回归挂起 |
| 允许域清单 | 是否需要子域（如 `app.` 前缀），是否需要 CDN 域留壳 | D2 | 默认只放行单一主机名 |
| 受控 Demo 账号 | 账号标识 + 口令交付方式（不写进仓库） | D5 | 回归用例 `test.skip` 并标记待 A 提供 |
| `/api/healthz` 响应结构 | 是否含 `status` / `db` 字段 | D5 | 探针只校验可达性与无敏感信息 |
| 会话过期策略 | Cookie 有效期、是否滑动续期 | D5 | 不在回归中断言具体时长 |
| Cookie 属性 | HttpOnly / Secure / SameSite 取值 | D5 | 探针记录告警，不阻断 |
| 恢复演练的独立环境 | A 负责的恢复部分所需环境与检查方式 | D10–D11 | 从证据表第 4 节拆出，标注“A 主责” |

**E 不会**：改 `docs/engineering/*`、根 `README.md`、A 的部署配置。

## 3. 依赖顺序（E 的可开工边界）

```
D1–D2  ✅ 现在可做：壳、运行时检测、安装方式、导航自检
D2     ⏳ 等 A：部署地址 → 壳联通验证
D3–D5  ✅ 现在可做：回归脚本（已就绪，等标识契约）
D6–D9  ⏳ 等 C/D：业务页面 → 失败分支串联
D10–D14 ⏳ 等全员：双端回归、安装包、演示
```

需要等队友的部分已全部落成**占位 + 单点常量**，接口就绪后改动量：改 1 个 JSON 文件、可能补几行 `data-testid`。

## 4. 提交约定

- E 只在 `desktop/`、`tests/e2e/`、`docs/qa/` 下新增文件。
- 不改他人文件；若需他人补 `data-testid`，由 E 提交 PR 说明清单，队友合并。
- `.gitignore` 已在 E 目录内单独声明，不影响根规则。
- 仓库公开：不提交凭证、真实域名口令、个人终端日志、供应商原始响应。
